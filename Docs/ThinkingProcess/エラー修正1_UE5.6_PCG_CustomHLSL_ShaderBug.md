# UE5.6 PCG CustomHLSL シェーダーコンパイルエラー 思考プロセス記録

## 概要
- 日付: 2025-12-30
- タスク種別: エラー修正
- 難易度: 高
- 所要時間: 約2時間

---

## フェーズ1: 問題の認識

t+0: [トリガー]
     UE5.6 でプロジェクトをパッケージ化しようとしたら、シェーダーコンパイルエラーが発生
     ```
     Error: ComputeKernel.ush(130,6): expected unqualified-id
     Error: syntax error: unexpected token '?'
     ```

t+1: [分類]
     - 種類: シェーダーコンパイルエラー（パッケージ化時）
     - 緊急度: 高（パッケージ化不可）
     - 影響範囲: PCG CustomHLSL を使用するすべてのアセット

---

## フェーズ2: 原因の特定

t+2: [仮説]
     1. 「UE5.7 からのダウングレードで互換性問題が発生したのでは？」
     2. 「PCG プラグインの設定が壊れたのでは？」
     3. 「シェーダーキャッシュが破損しているのでは？」

t+3: [検証方法の選択]
     | 選択肢 | 方法 | 採用 |
     |--------|------|------|
     | A | Engine の Intermediate/DDC を削除して再ビルド | ✓（最初に試行、失敗） |
     | B | エラーログからシェーダーファイルを特定 | ✓ |
     | C | PCG グラフを一つずつ無効化 | 後で試行 |

     選択理由: まずキャッシュクリアを試し、それでもダメならエラーの根本原因を追跡

t+4: [調査結果]
     エラーログを解析した結果:
     ```
     LogComputeFramework: /Engine/Transient/PCG_BiomeRealTime/カスタムHLSL_PCGCustomHLSLKernel: Shader compilation failed.
     ```

     → `PCG_BiomeRealTime` の CustomHLSL ノードが原因と特定
     → `?` トークンエラー = シェーダー圧縮（minification）バグの典型的症状

---

## フェーズ3: 解決策の設計

t+5: [候補の比較]

| 案 | 内容 | メリット | デメリット | 採用 |
|----|------|----------|------------|------|
| 1 | r.Shaders.AllowMinification=0 設定 | 設定変更のみ | UE5.6では効果なし | × |
| 2 | PCG フォルダを NeverCook に追加 | 簡単 | マップが参照してエラー | × |
| 3 | 問題のアセットのみ除外 | 影響範囲が限定的 | 依存関係で複雑化 | × |
| 4 | CustomHLSL ノードの接続を切断 | 根本解決 | エディタ作業が必要 | ✓ |
| 5 | UE5.5 にダウングレード | 確実 | 大きな後退 | × |

t+6: [選択理由]
     - 案1: UE5.6 ではシェーダーminification設定が別の場所で制御されており無効
     - 案2-3: マップが `BP_PCG_Biome_Bundled` → `PCG_BiomeRealTime` を参照しており、除外すると依存エラー
     - 案4: CustomHLSL ノードを無効化すれば、シェーダーコンパイル自体が発生しない
     - 案5: 最終手段として保留

## フェーズ4: 実装と検証

t+7: [実装内容]
     - 変更ファイル: `Content/ScifiJungle/PCG/Bundle/Graphs/Biome/PCG_BiomeRealTime.uasset`
     - 変更箇所: PCG グラフ内の CustomHLSL ノード
     - 変更内容: CustomHLSL ノードへの接続を切断（ノード自体は残す）

     ※この作業はUE5エディタで実施（uasset はバイナリファイルのため）

t+8: [検証結果]
     - 検証方法: エディタからパッケージ化を実行
     - 結果: 成功
     - 確認: ゲームが正常に起動し、PCG による植生配置も動作

## フェーズ5: 学びと次への活用

### 今回の判断軸
| 軸 | 説明 |
|----|------|
| 影響範囲の最小化 | PCG機能全体ではなく、問題のノードのみを無効化 |
| 依存関係の理解 | マップ → Blueprint → Graph の参照チェーンを把握 |
| エンジンバグの識別 | `?` トークンエラー = シェーダーminificationバグのパターン認識 |

### 次に活かすポイント
1. **UE5.6 で PCG CustomHLSL を使う場合は要注意**
   - シェーダーminificationバグが存在
   - パッケージ化前にエディタでシェーダーコンパイルを確認

2. **NeverCook 除外は依存関係を考慮**
   - 単純にフォルダ除外すると参照エラーになる
   - Reference Viewer で依存関係を確認してから除外

3. **エラーログの `?` トークン = minificationバグ**
   - 典型的な症状として記憶しておく
   - 対処: 問題のシェーダーを生成するノードを無効化

### パターン化
このタイプの問題が再発したら:
1. まずエラーログから問題のアセット名を特定（`/Engine/Transient/XXX`）
2. そのアセットの PCG グラフを開く
3. CustomHLSL ノードを探す
4. ノードの接続を切断（または削除）
5. 保存してパッケージ化を再試行

## 試行錯誤の詳細ログ

### 失敗した試み

1. **Engine Intermediate 削除**
   - 結果: AutomationTool が壊れ、Epic Launcher で Verify が必要に
   - 学び: Engine フォルダの Intermediate は削除しない

2. **r.Shaders.AllowMinification=0**
   - 結果: 効果なし
   - 学び: UE5.6 ではこの設定が別の場所で管理されている

3. **DirectoriesToNeverCook で PCG フォルダ除外**
   - 結果: マップが参照しているためエラー
   - 学び: 除外する前に Reference Viewer で確認

4. **特定アセットのみ除外**
   - 結果: BP_PCG_Biome_Bundled が PCG_BiomeRealTime を参照しており、除外すると連鎖的にエラー
   - 学び: アセットパックの内部依存は複雑
